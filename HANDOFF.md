## Resolved Blockers (2026-09-12)

- **CallsService DI failure (was blocking ALL 239 E2E tests)**: `CallsService` injected `ConversationsService`, but `CallsModule` did not import the module providing it. Fixed by introducing a shared `src/modules/chat/chat-core.module.ts` that provides+exports `ConversationsService`, imported by both `chat.module.ts` (re-exported as `ChatCoreModule`) and `calls/calls.module.ts`. A first attempt re-exported the provider directly from `chat.module.ts`, which NestJS v11 rejects; the correct fix re-exported the module.
- **OTP verification threw "No record was found for an update"**: `OtpService.verify()` now wraps the find+update in `prisma.$transaction` using `tx.otpCode`, eliminating the race where the row vanished between the read and the update.
- **Test DB had no schema**: migrations now applied to the isolated test database (`veakay-postgres-test`, port 57433) via `DATABASE_URL=... npx prisma migrate deploy`, including the `content_reports` table that `resetDb()` truncates.
- **MinIO bucket access**: `.env` had an empty `REDIS_PASSWORD` that crashed the redis container; set to `veakay_redis_password` to match `.env.test`. MinIO bucket `veakay-dev` recreated with correct root credentials.
- **Dashboard auth contract**: `login()` no longer expects a non-existent `requires2FA` field; admin login always proceeds to 2FA. `platformRole` is no longer required from the 2FA response. Middleware now reads a real `veakay-access-token` cookie set on successful 2FA (previously it checked a cookie that was never written, so every `/dashboard/*` request redirected to `/login`).
- **Mobile testing**: added `jest.config.js` (jest-expo preset), `jest.setup.js` (native module mocks), and a real component test. `npm test` now passes 2/2 and `npm run typecheck` is clean (previously `npm test` exited 1 with no tests).
